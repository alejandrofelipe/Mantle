# Migration guide — MC 1.21.1 → 1.21.4 (NeoForge 21.1.234 → 21.4.161)

Roadmap milestone **M1** (folds the old M1 1.21.2 + M2 1.21.4). Mantle `1.12 → 1.13`, TinkersConstruct
`3.11.3 → 3.12.0`. Branch `1.21.3` in both repos (name kept from the original target; it targets 1.21.4).
Plan: `tinkers/docs/superpowers/plans/2026-10-21-m1-1.21.4-port.md`.

This is the gotcha log — the things that cost iterations. The full API delta is in ChampionAsh5357's
`1.21.1 → 1.21.2` primer plus the NeoForge 21.2 / 21.4 release notes.

## Target choice
- NeoForge for **1.21.2 never left beta** (`21.2.0/1-beta`). 1.21.3 is stable (`21.3.x`).
- **JEI and Immersive Engineering skipped 1.21.2 and 1.21.3 entirely** (JEI goes `jei-1.21.1` → `jei-1.21.4`).
  A 1.21.3 checkpoint would ship with no JEI → we landed on **1.21.4**. Check compat availability *before*
  picking a checkpoint version, not just NeoForge.

## Toolchain
- NeoGradle **7.1.38 → 7.1.39** (21.4 needs it; Gradle wrapper stays **9.2.1**). Symptom of the old one:
  `The run type 'data' was not found`.
- The vanilla `data` run type is gone → **`clientData` + `serverData`**. We kept a block named `data`
  (`runType 'clientData'`, task `runData`) and added `serverData` (task `runServerData`).
- `--existing-mod` is no longer a recognised datagen arg (`ExistingFileHelper` removed) → drop it.
- Parchment `1.21.4 / 2025.03.23`; JEI `20.0.0.4` (new major → real plugin port).

## Datagen
- **Two runs, and they mutually purge.** Each run's HashCache deletes every output file it didn't produce
  itself — `clientData` deletes the server `data/`, `serverData` deletes the client `assets/`. Worse, the
  texture generators **skip files that already exist**, so a `clientData` run also "purges" ~10k generated
  part textures it didn't re-claim. Procedure: regenerate the side you changed, then
  `git restore` the other side (and untouched textures) from HEAD; commit only intended changes.
- `GatherDataEvent` → `GatherDataEvent.Server` / `.Client` (one listener each). `getExistingFileHelper()`,
  `includeServer()`, `includeClient()` are gone → `event.getGenerator()`, `getLookupProvider()`,
  `addProvider()`, `getResourceManager(PackType)`.
- `ExistingFileHelper` removed → providers read existing resources through `ResourceManager`.
- NeoForge `client.model.generators.*` removed → vanilla `net.minecraft.client.data.models.*`
  (`ModelProvider`, `BlockModelGenerators`); `CustomLoaderBuilder` moved to `…generators.template`,
  non-generic, needs `copyInternal()`. Override `getKnownBlocks/getKnownItems` so vanilla's validation only
  checks blocks your provider actually generates.
- `RecipeProvider` is no longer a `DataProvider` → `RecipeProvider.Runner`; `RecipeOutput#accept` /
  `RecipeBuilder#save` take `ResourceKey<Recipe<?>>`; `ShapedRecipeBuilder.shaped` & co. need a
  `HolderGetter<Item>`.
- Ingredient JSON is now holder-set form (`"minecraft:x"`, `"#c:tag"`). Tags referenced at datagen are
  unbound → resolve through the datagen `HolderLookup.Provider`, never `BuiltInRegistries.getOrThrow`.

## Registration — compiles fine, crashes at runtime
- `Item.Properties` / `BlockBehaviour.Properties` **must** carry `.setId(ResourceKey)` before construction.
  Supplier-form registrations (`register(name, () -> new X(props))`) still **compile** but throw
  `Block id not set` at mod load. Migrate to Function-form (`register(name, X::new, props)`) so the register
  injects the id. Mantle's deferred registers grew id-setting Function/enum/building overloads for this.
- `BlockEntityType.Builder` removed → `new BlockEntityType<>(factory, blocks...)`.

## Tags
- `Ingredient.of(TagKey)` was **removed**. `Ingredient.of(BuiltInRegistries.ITEM.getOrThrow(tag))` is eager
  and crashes with `Tags not bound` when evaluated at class-load/registration. Tinkers' `LazyTagIngredient`
  is a `HolderSet` that serialises as `#tag` and resolves contents on first use.
- Vanilla tag renames hit data: `minecraft:trim_templates` no longer exists; `c:slimeballs` → `c:slime_balls`.

## Serialization (the long tail)
- `JsonOps.INSTANCE` cannot decode holder-set ingredients ("without registry"). Mantle now resolves a
  registry-aware ops via `RegistryJsonOps` and threads the caller's ops through the loadable context
  (`ContextKey.OPS`) — recipes, ingredients, conditions, fluid transfers, GSON loot conditions.
- At **datapack reload**, datapack tags are not bound to `BuiltInRegistries` yet → use NeoForge's injected
  `getRegistryLookup()` (staged tags), not the built-in registry fallback. Conditions must use
  `context.isTagLoaded(tag)`, not registry contents. **Every** `SimpleJsonResourceReloadListener` that decodes
  tag ingredients needs this — put the ops in `ContextKey.OPS` (loadables) or `RegistryJsonOps.withThreadedOps`
  (GSON). The fallback fails only on the **first boot** (a later `/reload` sees the previous reload's tags), so
  a client that reloads hides it; `ModifierManager` and `StationSlotLayoutLoader` silently dropped 2 modifiers
  and 3 required station layouts this way until the gametest log was read (guard:
  `tag_ingredient_runtime_data_loads_on_first_boot`).
- **Client recipe sync decodes over `RegistryOps<Tag>` (NbtOps)**, while Mantle's `JsonCodec` converts the
  input to JSON → `LoadableCodec` must re-parent the threaded ops to `JsonOps`
  (`registryOps.withParent(JsonOps.INSTANCE)`). Before that fix: `ClassCastException` →
  `Failed to decode packet 'clientbound/minecraft:custom_payload'` → *Connection Lost* on every world join.

## Recipes
- Recipes are a datapack registry: `display()` / `placementInfo()` / `recipeBookCategory()` replace
  `getResultItem`/`getToastSymbol`/`getIngredients`/`canCraftInDimensions`; `RecipeHolder#id()` is a
  `ResourceKey`; `getType()/getSerializer()` became covariant-bounded.
- `Level#getRecipeManager()` → `recipeAccess()` — and only `ServerLevel` returns a full `RecipeManager`.
  **The client has no RecipeManager**: it gets a `RecipeMap` from `RecipesReceivedEvent`, containing only
  the types the server opted into via `OnDatapackSyncEvent#sendRecipes`. Tinkers' `TinkerRecipeAccess`
  picks server-manager vs synced-client-map; any `getServer().getRecipeManager()` reachable on the client
  NPEs and drops the player.

## Items / interaction / components
- `InteractionResultHolder` + `ItemInteractionResult` removed; `InteractionResult` is sealed. A changed held
  stack goes through `InteractionResult.SUCCESS.heldItemTransformedTo(stack)`.
- `isDamageableItem()` is now pure **component presence** (`MAX_DAMAGE` + `DAMAGE`). Tools built without
  them report `getMaxDamage() == 0` → set the components on built tool stacks (values are inert markers;
  the dynamic durability still comes from the override).
- `Tier`/`Tiers`/`TieredItem` gone → `ToolMaterial` record; `ArmorItem.Type` → `ArmorType`; food effects
  moved to the `Consumable` component; `UseAnim` → `ItemUseAnimation`.

## Item models (the biggest wall)
- `neoforge.client.model.geometry.*`, `ItemOverrides`, `BakedOverrides`, `BakedModelWrapper` are gone.
  Block models: `AbstractUnbakedModel` + `UnbakedModelLoader` (`ModelEvent.RegisterLoaders`). Item models:
  `ItemModel.Unbaked` (MapCodec, `RegisterItemModelsEvent`) + `assets/<ns>/items/<id>.json`.
- 1.21.4's `LayerRenderState.setupBlockModel(BakedModel, RenderType)` takes a **whole BakedModel**, and
  `applyTransform` only sets the pose → gui/left/right variant selection moves into `ItemModel#update()`.
- `ItemModel.Unbaked` has **no texture-dependency hook**: sprites looked up by name at bake must be put in
  the atlas explicitly (`directory("item/tool")` sprite source) or they render missing-texture.
- `ItemModel.Unbaked#bake` runs **before the block atlas exists** → bake sprite-dependent variants lazily.
- Custom-loader wrappers that inherit their geometry must delegate to the parent when they have no own
  elements (`ColoredBlockModel.bake`), or the item renders blank.
- Datagen item JSON must match the codec exactly (`first_modifiers` objects, not strings).
- `ItemColors` registration is gone; Tinkers bakes material/modifier tint into quads instead.

## Rendering
- `GuiGraphics.blit(RenderType::guiTextured, rl, x, y, u, v, w, h, texW, texH)`; `setColor` removed.
- Entities: `EntityRenderer<E, S>` + `createRenderState()` / `extractRenderState()`; `Model#renderToBuffer`
  is final; armor renders through `EquipmentClientInfo` / `EquipmentLayerRenderer`.
- Shaders: `ShaderProgram` + `RegisterShadersEvent.registerShader`; `CoreShaders.*` constants.

## Verification lessons
Each gate hid the next class of bug — run all of them:
compile+build+unit (pure logic) **≠** mod loads (`setId`, eager tags) **≠** gametests pass (server-only,
misses client sync) **≠** client joins (recipe-sync decode) **≠** uitest `"ok"` (no crash, but pixels can
still be missing-texture — *look at the screenshots*).

## Known issues (shipped with v1.21.4)
- Immersive Engineering (no 1.21.4 build) and JSON Things (maven down) are excluded.
- 12 lustrous modifiers stay inert without a compat mod that adds the `c:ores/<metal>` item tags.
- Raw-steel melting recipes only activate if a mod provides `c:raw_materials/steel`.
- `#tconstruct:smithing_templates` covers vanilla templates only (add others via datapack).
- Deferred visual approximations (`// PORT 1.21.4:` breadcrumbs): crossbow ammo overlay, dynamic armor
  texture fidelity, slimeskull embedded skull, `NBTKeyModel` item variants (default only), potion fluid
  client tint.
