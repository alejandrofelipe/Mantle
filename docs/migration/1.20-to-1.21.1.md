# Mantle migration guide: MC 1.20.1 / Forge → MC 1.21.1 / NeoForge

## 1. Introduction

This guide documents, subsystem by subsystem, what changed in Mantle's public surface when it was
ported from **Minecraft 1.20.1 on Forge** to **Minecraft 1.21.1 on NeoForge 21.1.234**. It exists so
that someone porting a Mantle-dependent mod (Tinkers' Construct, or your own) can find the new symbol
for each old one without re-deriving it.

Two large shifts overlap here, which is why so much moved at once:

1. **A four-version Minecraft jump** (1.20.1 → 1.21.1). Vanilla itself rewrote item/fluid storage,
   serialization, model baking, and several method signatures.
2. **A loader change** (Forge → NeoForge). Every `net.minecraftforge.*` package moved to
   `net.neoforged.neoforge.*` (or `net.neoforged.fml.*` / `net.neoforged.bus.*`), and several Forge
   subsystems were redesigned rather than merely repackaged.

### Headline conceptual shifts

- **Item/fluid NBT → data components.** `ItemStack`/`FluidStack` no longer carry a free-form
  `CompoundTag`. Per-stack data lives in typed *data components* (`DataComponents.*`), and the
  "extra data" on a stack is a `DataComponentPatch`. Methods like `stack.getTag()`/`stack.hasTag()`
  are gone.
- **Capabilities rework.** Forge's `Capability<T>` + `LazyOptional<T>` + `ICapabilityProvider` were
  replaced by NeoForge's `BlockCapability`/`ItemCapability` look-up objects (`Capabilities.*`),
  resolved through `level.getCapability(...)` / `stack.getCapability(...)` returning a plain
  `@Nullable` value, and registered in a single `RegisterCapabilitiesEvent`.
- **Payload networking.** `SimpleChannel` + `registerMessage` were replaced by
  `CustomPacketPayload` records, each with a `Type` and a `StreamCodec`, registered on
  `RegisterPayloadHandlersEvent`.
- **Codec / `MapCodec` serialization.** Recipe serializers, ingredient/condition types, and loot
  pieces no longer expose `fromJson`/`toNetwork` methods; they expose a `MapCodec` (JSON/data) plus a
  `StreamCodec` (network).
- **Mojmap access transformers.** The AT file uses readable Mojang names (`entries`, `parent`)
  instead of SRG names (`f_xxx_`, `m_xxx_`), and is declared via `minecraft.accessTransformers` in
  `build.gradle`.

### Mantle-specific addition: the `Loadable` codec bridge

Mantle's `Loadable<T>` framework predates codecs and is still the recommended way to describe Mantle
data. To make loadables usable everywhere 1.21 now *demands* a codec, the port added three bridge
methods (see [§4](#4-data--loadables)):

```java
Loadable<T>           // gains:
Codec<T>                          codec();       // JSON ops bridge
StreamCodec<RegistryFriendlyByteBuf, T> streamCodec();  // network bridge
RecordLoadable<T>     // additionally gains:
MapCodec<T>                       mapCodec();     // for recipe/ingredient/condition serializers
```

So in ported code you keep writing loadables and call `.mapCodec()` / `.streamCodec()` at the seam
where vanilla/NeoForge wants a codec.

### How to read the tables

Each section has a **before → after** table. The left column is the 1.20.1/Forge symbol (the line
that was *removed* in the port commits); the right column is the real 1.21.1/NeoForge symbol that
replaced it (verified against `src/main/java/slimeknights/mantle`). Fully-qualified names are
shortened to the meaningful part. A short *Why* and *How to adapt* follow, plus a link to the
matching API how-to guide.

## 2. Build & toolchain

The build moved from ForgeGradle to NeoGradle userdev, bumped to Java 21, and renamed the mod
metadata file.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `id 'net.minecraftforge.gradle' version '[6.0,…]'` | `id 'net.neoforged.gradle.userdev' version '7.0.190'` | NeoGradle userdev plugin |
| `id 'org.parchmentmc.librarian.forgegradle'` | `subsystems { parchment { … } }` | Parchment is now a NeoGradle subsystem |
| `JavaLanguageVersion.of(17)` | `JavaLanguageVersion.of(21)` | MC 1.21 requires Java 21 |
| `minecraft { mappings channel: 'parchment' … }` | (handled by NeoGradle + `subsystems.parchment`) | mojmap is the base mapping |
| `minecraft { accessTransformer = file(...) }` | `minecraft { accessTransformers { file('…/accesstransformer.cfg') } }` | new DSL block |
| SRG AT names: `public … BlockModel f_111419_` | mojmap AT names: `public-f … LootPool entries` | mojmap mappings; SRG `f_xxx_`/`m_xxx_` no longer resolve |
| `src/main/resources/META-INF/mods.toml` | `src/main/resources/META-INF/neoforge.mods.toml` | renamed; uses `[[accessTransformers]]`, `type="required"` (was `mandatory=true`), `modId="neoforge"` |
| Gradle wrapper 8.x | Gradle **9.2.1** + NeoGradle **7.1.38** | plugin and Gradle versions are paired — keep them in lockstep |

*Why:* NeoForge ships a mojmap-mapped runtime, which forces the AT-name change, the metadata rename,
and a toolchain that understands NeoForge userdev.

*How to adapt:* rename `mods.toml` → `neoforge.mods.toml`, regenerate your AT entries with mojmap
names (drop any that the port made redundant by using public APIs), switch the Gradle plugins, and
target Java 21. Do not downgrade the wrapper independently of the plugin.

## 3. Registration

Forge's `DeferredRegister`/`RegistryObject` and `IForgeRegistry` adapters became NeoForge's
`DeferredRegister`/`DeferredHolder` and vanilla `Registry`.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `RegistryObject<T>` | `DeferredHolder<R, T>` | now two type params: registry type `R` and value type `T` (e.g. `DeferredHolder<Block, B>`) |
| `net.minecraftforge.registries.DeferredRegister` | `net.neoforged.neoforge.registries.DeferredRegister` | repackaged |
| `IForgeRegistry<T>` (adapter ctor arg) | `net.minecraft.core.Registry<T>` | adapters take a vanilla `Registry` |
| `ForgeRegistries.ITEMS` / `.BLOCKS` | `BuiltInRegistries.ITEM` / `.BLOCK` | vanilla built-in registries |
| `ForgeRegistries.Keys.FLUID_TYPES` | `NeoForgeRegistries.Keys.FLUID_TYPES` | NeoForge-owned registry keys |
| `IForgeMenuType.create(factory)` | `IMenuTypeExtension.create(factory)` | menu type factory |
| `net.minecraftforge.network.IContainerFactory` | `net.neoforged.neoforge.network.IContainerFactory` | repackaged |
| `@ObjectHolder(...)` field injection | removed | assign holders manually after registration (e.g. `MantleRegistrations.SIGN` is now a plain field) |
| `MissingMappingsEvent` / `mapping.remap(...)` | removed | no NeoForge equivalent; remapping legacy IDs is dropped |
| `ForgeFlowingFluid` / `ForgeFlowingFluid.Properties` | `BaseFlowingFluid` / `BaseFlowingFluid.Properties` | also affects `FluidBuilder`, `FluidDeferredRegister` |

*Why:* NeoForge unified its deferred registration on `DeferredHolder` (a `Holder` subtype) and routes
everything through vanilla `Registry` objects; Forge-only injection/remapping events were removed.

*How to adapt:* replace `RegistryObject<T>` with `DeferredHolder<R, T>` (supplying both type
parameters), swap `ForgeRegistries.X` for `BuiltInRegistries.X` / `NeoForgeRegistries.Keys.X`, and
stop relying on `@ObjectHolder`/`MissingMappingsEvent`.

See the [registration guide](../api/registration.md).

## 4. Data & Loadables

The `Loadable` framework compiles unchanged in spirit, but stack fields now serialize
`DataComponentPatch` instead of NBT, and loadables gained codec bridges so they slot into 1.21's
codec-everywhere APIs.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| *(none)* | `Loadable#codec()` → `Codec<T>` | new bridge over `JsonOps` |
| *(none)* | `Loadable#streamCodec()` → `StreamCodec<RegistryFriendlyByteBuf, T>` | new bridge over the buffer encode/decode |
| *(none)* | `RecordLoadable#mapCodec()` → `MapCodec<T>` | wraps `codec()` via `MapCodec.assumeMapUnsafe` |
| `NBTLoadable` field `"nbt"` on stacks | `DataComponentPatch` field `"components"` | JSON key `nbt` → `components` |
| `FluidStack::getTag` / `ItemStack::getTag` | `FluidStack::getComponentsPatch` / `ItemStack::getComponentsPatch` | patch getters |
| `!stack.hasTag()` (compact check) | `FluidStack::isComponentsPatchEmpty` | "is this stack plain?" |
| `ItemDisplayContext` via registry lookup | `ItemDisplayContext` as `StringRepresentable` enum | no longer a registry |
| `net.minecraftforge.common.crafting.conditions.ICondition` | `net.neoforged.neoforge.common.conditions.ICondition` | conditions via `ICondition.LIST_CODEC` / `CODEC` + `IContext` |
| `net.minecraftforge.common.data.ExistingFileHelper` | `net.neoforged.neoforge.common.data.ExistingFileHelper` | repackaged |
| `ToolAction` | `ItemAbility` | also in data predicates |

*Why:* 1.21 stores per-stack data as components, so any loadable describing a stack stores a
`DataComponentPatch`; and because vanilla/NeoForge serializers are now codec-based, loadables needed a
first-class way to expose codecs.

*How to adapt:* change JSON that wrote `"nbt": {...}` to `"components": {...}`; where you previously
handed Mantle a serializer, call `.mapCodec()` / `.streamCodec()` on the loadable at the codec seam.

See the [data & loadables guide](../api/data-loadables.md).

## 5. Predicates

The only structural change is that `MobType` was removed from vanilla; entity-category predicates now
match against **entity-type tags**.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `record MobTypePredicate(MobType type)` | `record MobTypePredicate(TagKey<EntityType<?>> tag)` | tag-based |
| `NamedComponentRegistry<MobType> MOB_TYPES` | `Loadables.ENTITY_TYPE_TAG` field | tag loadable replaces the named registry |
| `input.getMobType() == type` | `input.getType().builtInRegistryHolder().is(tag)` | match by tag membership |
| `net.minecraft.world.entity.MobType` | (removed) | use tags like `minecraft:undead`, `minecraft:arthropod`, `minecraft:illager`, `minecraft:aquatic` |

*Why:* Mojang deleted the `MobType` enum in 1.21 in favour of data-driven entity-type tags.

*How to adapt:* replace `MobType` references with the corresponding vanilla entity-type tag and match
via `entity.getType().builtInRegistryHolder().is(tag)`. Old JSON naming a mob type must now name an
entity-type tag.

See the [predicates guide](../api/predicates.md).

## 6. Fluids

`FluidStack` became component-based (it no longer wraps an NBT tag and is no longer constructed from
another stack), and fluid handler capabilities are resolved the NeoForge way.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `net.minecraftforge.fluids.FluidStack` | `net.neoforged.neoforge.fluids.FluidStack` | repackaged + component-based |
| `new FluidStack(stack, amount)` | `stack.copyWithAmount(amount)` | copy with a new amount |
| `new FluidStack(fluid, amount, nbt)` | `new FluidStack(fluid, amount, patch)` | `DataComponentPatch` instead of `CompoundTag` |
| `stack.isFluidEqual(other)` | `FluidStack.isSameFluidSameComponents(a, b)` | component-aware equality |
| `fluidStack.getDisplayName()` | `fluidStack.getHoverName()` | renamed |
| `ForgeCapabilities.FLUID_HANDLER` | `Capabilities.FluidHandler.BLOCK` | block fluid handler lookup |
| `ForgeCapabilities.FLUID_HANDLER_ITEM` | `Capabilities.FluidHandler.ITEM` | item fluid handler lookup |
| `te.getCapability(cap, side)` → `LazyOptional<IFluidHandler>` | `level.getCapability(Capabilities.FluidHandler.BLOCK, pos, side)` → `@Nullable IFluidHandler` | resolved on the level, null when absent |
| `stack.getCapability(cap)` → `LazyOptional<IFluidHandlerItem>` | `stack.getCapability(Capabilities.FluidHandler.ITEM)` → `@Nullable IFluidHandlerItem` | no `LazyOptional` |
| `ForgeFlowingFluid` | `BaseFlowingFluid` | base flowing fluid class |
| `EventHooks.canCreateFluidSource(level, pos, state, bool)` | `EventHooks.canCreateFluidSource(level, pos, state)` | 3-arg now |
| `net.minecraftforge.fluids.FluidType` | `net.neoforged.neoforge.fluids.FluidType` | repackaged |

*Why:* component storage replaced NBT for fluids too, and capability resolution moved off
`LazyOptional` onto direct nullable lookups via `Capabilities.*`.

*How to adapt:* replace `new FluidStack(other, n)` with `other.copyWithAmount(n)`; replace
`isFluidEqual` with `isSameFluidSameComponents`; and rewrite capability access as
`level.getCapability(Capabilities.FluidHandler.BLOCK, pos, side)` / `stack.getCapability(
Capabilities.FluidHandler.ITEM)`, null-checking the result instead of `.isPresent()`.

See the [fluids guide](../api/fluids.md).

## 7. Recipes

Recipe serializers, conditions, ingredient extensions, and datagen builders all moved to codecs and
to `RecipeOutput`/`RecipeHolder`.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `RecipeSerializer#fromJson(id, json)` | `RecipeSerializer#codec()` → `MapCodec<R>` | JSON/data path is now a codec |
| `RecipeSerializer#toNetwork` / `#fromNetwork` | `RecipeSerializer#streamCodec()` → `StreamCodec<RegistryFriendlyByteBuf, R>` | network path is a stream codec |
| `LoggingRecipeSerializer<R>` (custom base) | `RecipeSerializer<R>` with `codec()` + `streamCodec()` | bespoke base no longer needed |
| `Consumer<FinishedRecipe>` | `RecipeOutput` | datagen sink (`net.minecraft.data.recipes.RecipeOutput`) |
| `consumer.accept(finishedRecipe)` | `output.accept(id, recipe, advancement, conditions...)` | `RecipeOutput` carries conditions directly |
| recipe identity passed per-serializer | `RecipeHolder<R>` (id + value) | derived display data computed from `RecipeHolder#value()` |
| Forge `ICondition` recipe conditions | NeoForge `ICondition` with `MapCodec<? extends ICondition> codec()` | e.g. `TagFilledCondition.CODEC` |
| Forge custom ingredients | `ICustomIngredient` | NeoForge custom ingredient interface |
| `net.minecraftforge.registries.RegistryObject` (in recipe helpers) | `net.neoforged.neoforge.registries.DeferredHolder` | helper return types |

*Why:* 1.21 unified recipe (and condition/ingredient) serialization on `MapCodec` + `StreamCodec`,
and replaced the `FinishedRecipe` callback with `RecipeOutput`, which threads conditions and
advancements through one object.

*How to adapt:* give each custom serializer a static `MapCodec` and `StreamCodec` and return them
from `codec()`/`streamCodec()` (you can build them from a Mantle loadable via `.mapCodec()` /
`.streamCodec()`); change datagen method signatures from `Consumer<FinishedRecipe>` to `RecipeOutput`.

See the [recipes guide](../api/recipes.md).

## 8. Networking

Mantle's network layer was rewritten over NeoForge's payload system: each packet is a record
implementing `CustomPacketPayload`.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `SimpleChannel` | `PayloadRegistrar` (from `event.registrar(version)`) | obtained in the event |
| `channel.registerMessage(id, type, encode, decode, handle)` | `registrar.playToClient(TYPE, STREAM_CODEC, handler)` / `registrar.playToServer(...)` | direction is the method name |
| register in constructor / `FMLCommonSetupEvent` | register on `RegisterPayloadHandlersEvent` (mod bus) | new event |
| `class Packet implements ISimplePacket` | `record Packet(...) implements ISimplePacket` (extends `CustomPacketPayload`) | packets are records |
| `void encode(FriendlyByteBuf buf)` + `Packet(FriendlyByteBuf)` ctor | `static StreamCodec<RegistryFriendlyByteBuf, P> STREAM_CODEC` | (de)serialization is a stream codec |
| `NetworkDirection.PLAY_TO_CLIENT` / `PLAY_TO_SERVER` | `registrar.playToClient(...)` / `playToServer(...)` | direction chosen at registration |
| `void handle(Supplier<NetworkEvent.Context>)` | `void handle(IPayloadContext context)` | context is passed directly |
| `context.enqueueWork(...)` + `context.setPacketHandled(true)` | `context.enqueueWork(...)` | no `setPacketHandled` |
| `registerMessage` index/id | `CustomPacketPayload.Type<P>` (a `ResourceLocation`) | each payload declares a `TYPE` |
| `ByteBuf` enum read/write helpers | `NeoForgeStreamCodecs.enumCodec(...)`, `ByteBufCodecs.*` | compose stream codecs |

*Why:* vanilla 1.20.5+ replaced ad-hoc channels with typed `CustomPacketPayload`s, and NeoForge wraps
registration in `RegisterPayloadHandlersEvent` with a per-direction registrar.

*How to adapt:* turn each packet into a `record` implementing `CustomPacketPayload`, add a static
`TYPE` and `STREAM_CODEC`, change `handle` to take `IPayloadContext`, and register on
`RegisterPayloadHandlersEvent` via `playToClient` / `playToServer`. Note `event.registrar(String)`
takes the protocol **version**, not a namespace — the namespace comes from each payload's `Type`.

See the [networking guide](../api/networking.md).

## 9. Capabilities

Forge's capability system (`Capability`, `LazyOptional`, `ICapabilityProvider`) was replaced
wholesale by NeoForge's look-up objects and a single registration event.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `Capability<T>` (token) | `BlockCapability<T, C>` / `ItemCapability<T, C>` | typed look-up objects under `Capabilities.*` |
| `ForgeCapabilities.ITEM_HANDLER` | `Capabilities.ItemHandler.BLOCK` | block item handler |
| `ForgeCapabilities.FLUID_HANDLER` / `_ITEM` | `Capabilities.FluidHandler.BLOCK` / `.ITEM` | fluid handlers |
| `LazyOptional<T>` | plain `@Nullable T` | `null` means "not present"; no `.isPresent()`/`.orElse()` |
| `te.getCapability(cap, side)` | `level.getCapability(Capabilities.X.BLOCK, pos, side)` | resolved on the level/stack, not the BE |
| `implements ICapabilityProvider` + `getCapability(...)` override | `@Nullable IItemHandler getItemHandler(Direction)` exposed; registered centrally | BE exposes a getter; no per-BE provider |
| capability registration ad-hoc | `RegisterCapabilitiesEvent` (mod bus) | `event.registerBlock(...)` / `event.registerItem(...)` |
| `RegisterCapabilitiesEvent` (`net.minecraftforge.common.capabilities`) | `net.neoforged.neoforge.capabilities.RegisterCapabilitiesEvent` | repackaged + redesigned |

*Why:* NeoForge dropped the `Capability` token/`LazyOptional` model for direct, null-returning
look-ups registered once per block/item entity type in `RegisterCapabilitiesEvent`.

*How to adapt:* delete `ICapabilityProvider`/`getCapability` overrides and `LazyOptional` plumbing;
expose your handler via a getter (e.g. `getItemHandler(side)`) and register it with
`event.registerBlock(Capabilities.ItemHandler.BLOCK, (level, pos, state, be, side) -> …, blockEntityType)`
in a `RegisterCapabilitiesEvent` handler on the mod bus. At call sites, replace
`cap.isPresent()/orElse(...)` with a `null` check on the lookup result.

See the [registration guide](../api/registration.md) (capability registration lives alongside the
other mod-bus events).

## 10. Client & Models

Unbaked geometry baking lost its `ResourceLocation` parameter, and several rendering helpers moved to
NeoForge packages.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `IUnbakedGeometry#bake(ctx, baker, spriteGetter, transform, overrides, modelLocation)` (6-arg) | `IUnbakedGeometry#bake(ctx, baker, spriteGetter, transform, overrides)` (5-arg) | trailing `ResourceLocation` dropped |
| `net.minecraftforge.client.model.geometry.IUnbakedGeometry` | `net.neoforged.neoforge.client.model.geometry.IUnbakedGeometry` | repackaged |
| `IGeometryLoader` (Forge) | `net.neoforged.neoforge.client.model.geometry.IGeometryLoader` | repackaged |
| Forge `ModelData` / model-data builder | `net.neoforged.neoforge.client.model.data.ModelData` | repackaged |
| `forge:` model loader ids | `neoforge:` loader ids | resource JSON ids |

*Why:* the 1.21 model loader passes context differently and no longer needs the model location at
bake time; NeoForge repackaged the client model API.

*How to adapt:* drop the final `ResourceLocation` parameter from every `bake(...)` override (Mantle's
models such as `SimpleBlockModel`, `ConnectedModel`, `RetexturedModel`, `NBTKeyModel`,
`ColoredBlockModel`, `MantleItemLayerModel` are all 5-arg now), and update model-loader package
imports and JSON `loader` ids from `forge:` to `neoforge:`.

See the [client & models guide](../api/client-models.md).

## 11. Items & Blocks

Block interaction, tooltips, NBT signatures, and several item/food APIs changed in vanilla 1.21,
independent of the loader.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `Block#use(state, level, pos, player, hand, hit)` | `Block#useWithoutItem(state, level, pos, player, hit)` | `protected`; no `InteractionHand` param |
| `appendHoverText(stack, @Nullable Level/BlockGetter, tooltip, flag)` | `appendHoverText(stack, Item.TooltipContext context, tooltip, flag)` | 2nd param is `Item.TooltipContext` |
| `getCloneItemStack(state, target, level, pos, player)` | `getCloneItemStack(LevelReader level, pos, state)` | pick-block signature changed |
| `NetworkHooks.openScreen(serverPlayer, provider, pos)` | `serverPlayer.openMenu(provider, pos)` | open a menu directly |
| `ToolAction` / `ToolActions.AXE_STRIP` | `ItemAbility` / `ItemAbilities.AXE_STRIP` | tool actions renamed |
| `entity.setSecondsOnFire(n)` | `entity.igniteForSeconds(n)` | renamed |
| `saveAdditional(CompoundTag)` | `saveAdditional(CompoundTag, HolderLookup.Provider)` | BE NBT now takes registry access |
| `load(CompoundTag)` | `loadAdditional(CompoundTag, HolderLookup.Provider)` | BE NBT load |
| `getUpdateTag()` | `getUpdateTag(HolderLookup.Provider)` | sync tag |
| `stack.save(nbt)` / `ItemStack.of(nbt)` | `stack.save(registries, nbt)` / `ItemStack.parseOptional(registries, nbt)` | stack (de)serialization needs registries |
| `ItemHandlerHelper.copyStackWithSize(stack, n)` | `stack.copyWithCount(n)` | vanilla method |
| `ItemHandlerHelper.canItemStacksStack(a, b)` / `isSameItemSameTags` | `ItemStack.isSameItemSameComponents(a, b)` | component-aware |
| `Item#foodProperties` field + `Objects.requireNonNull(foodProperties, …)` | `DataComponents.FOOD` (`components().get(DataComponents.FOOD)`) | food is a data component |
| `FoodProperties#getEffects()` → `List<Pair<MobEffectInstance, Float>>` | `FoodProperties#effects()` → `List<FoodProperties.PossibleEffect>` | `possible.effect()` / `possible.probability()` |
| `ArmorMaterial` (enum-ish) | `Holder<ArmorMaterial>` | armor material is a holder |
| `DistExecutor.unsafeRunWhenOn(...)` | `FMLEnvironment.dist` guard + client-only holder class | `DistExecutor` removed |
| `net.minecraftforge.items.SlotItemHandler` / `IItemHandler` | `net.neoforged.neoforge.items.*` | repackaged |

*Why:* 1.21 split block interaction into item/no-item paths, routed BE NBT and stack serialization
through `HolderLookup.Provider`, and moved food onto the data-component system; NeoForge repackaged
the item-handler classes and removed `DistExecutor`.

*How to adapt:* rename `use` → `useWithoutItem` (dropping `InteractionHand`), update
`appendHoverText`'s second parameter to `Item.TooltipContext`, add the `HolderLookup.Provider`
argument to every BE NBT override and stack `save`/parse call, swap `copyStackWithSize` for
`copyWithCount`, and read food via `DataComponents.FOOD`.

See the [utilities guide](../api/utilities.md) and the [books guide](../api/books.md) for the
helper-level details (`RetexturedHelper`, lectern books, tooltips).

## 12. Entrypoint

The `@Mod` class now receives the mod's event bus and container as constructor arguments instead of
fetching them from a static context.

| 1.20.1 (Forge) | 1.21.1 (NeoForge) | Notes |
| --- | --- | --- |
| `public Mantle()` (no-arg ctor) | `public Mantle(IEventBus bus, ModContainer container)` | bus + container injected |
| `FMLJavaModLoadingContext.get().getModEventBus()` | the injected `IEventBus bus` | no static lookup |
| `ModLoadingContext.get().registerConfig(Type.CLIENT, spec)` | `container.registerConfig(ModConfig.Type.CLIENT, spec)` | config registered on the container |
| `net.minecraftforge.common.ForgeConfigSpec` | `net.neoforged.neoforge.common.ModConfigSpec` | (and `.Builder`, `.BooleanValue`, etc.) |
| `MinecraftForge.EVENT_BUS` | `NeoForge.EVENT_BUS` | game event bus |
| `net.minecraftforge.fml.*` (FML classes) | `net.neoforged.fml.*` / `net.neoforged.bus.api.*` | repackaged |
| `MantleNetwork.registerPackets()` (called at setup) | `bus.addListener(RegisterPayloadHandlersEvent.class, MantleNetwork::registerPayloads)` | payloads on the mod bus |
| `ForgeRegistries` / `RegisterEvent` (Forge) | `net.neoforged.neoforge.registries.RegisterEvent` | repackaged |
| `defineList(key, default, validator)` | `defineList(key, default, () -> "minecraft", validator)` | `ModConfigSpec` requires an element supplier |

*Why:* NeoForge injects the per-mod `IEventBus` and `ModContainer` into the mod constructor, so the
old static `FMLJavaModLoadingContext` / `ModLoadingContext` accessors are gone, and config is
registered through the container.

*How to adapt:* change your `@Mod` class constructor to `(IEventBus bus, ModContainer container)`,
use `bus` directly for mod-bus listeners, register config via `container.registerConfig(...)`, swap
`ForgeConfigSpec` for `ModConfigSpec`, and wire payload registration with
`bus.addListener(RegisterPayloadHandlersEvent.class, …)`.

See the [registration guide](../api/registration.md) for how Mantle's deferred registers are attached
to this bus.
