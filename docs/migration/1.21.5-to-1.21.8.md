# Migration gotchas: 1.21.5 → 1.21.8 (roadmap M4)

Companion to [`1.21.4-to-1.21.5.md`](1.21.4-to-1.21.5.md). Target: **MC 1.21.8 / NeoForge 21.8.57**, Parchment
`1.21.8 / 2025.09.14`, JEI `24.2.0.6`; 1.21.6 and 1.21.7 folded in. Branch `1.21.8` in both repos. Release targets
(not tagged yet): Mantle `1.15`, Tinkers `3.14.0`. Plan: `tinkers/docs/superpowers/plans/2026-10-24-m4-1.21.8-port.md`.

Practically every break comes from 1.21.6; the 1.21.7/1.21.8 primers had no impact here. The compiler found 102 errors
in Mantle (M3: 258) and 546 in Tinkers, but most of the real cost was **silent visual breakage** that only the uitest
screenshots show.

## Target choice & toolchain

- NeoForge **21.6 and 21.7 never left beta** (`21.6.20-beta` / `21.7.25-beta`), and **JEI skipped 1.21.6** → 1.21.8 is
  the first stable, JEI-supported step (same pattern as M1 skipping 1.21.2/1.21.3).
- Toolchain unchanged: NeoGradle **7.1.39** + Gradle **9.2.1**, Java 21 (matches `MDK-1.21.8-NeoGradle`).
- Pins: JEI `24.2.0.6` (new major, but the API is source-compatible — a `javap` diff of the four API jars showed two
  additions, nothing removed, identical deprecations; the work is the 1.21.6 GUI inside the plugin), Crafting Tweaks
  `21.8.2+1.21.8` + Balm `21.8.9+1.21.8`. Immersive Engineering (1.21.1 only) and JSON Things (builds for 1.21.6 and
  1.21.10+, none for 1.21.8) stay excluded.

## GUI — deferred render state (the biggest wall)

1.21.6 turned `GuiGraphics` into a recorder: draw calls submit render states, and the GUI renderer draws them later.

- `graphics.pose()` is a **`Matrix3x2fStack`**: `pushMatrix/popMatrix`, 2-arg `translate/scale`, `rotate`; no z.
- Blits take a pipeline: `blit/blitSprite(RenderPipelines.GUI_TEXTURED, …)`, `fill(RenderPipeline, …)`. Removed:
  `RenderType.gui*()` factories (`RenderType::guiTextured` method refs), `flush()`, `drawSpecial`, `bufferSource`,
  `fill(RenderType, …, z)`, `MAX/MIN_GUI_Z`.
- **Depth/z tricks → `graphics.nextStratum()`** at the same point of the draw order (the 1.21.5 `flush()` + clear-depth
  idiom is gone). Tinkers: `TinkerStationScreen` before the item cover, `InfoPanelScreen.beginOverlayStratum`.
- **`RenderSystem.setShaderColor` is gone → the color goes into the blit** (`blit(..., ARGB.color(a, rgb))`). JEI's
  `IDrawable.draw` takes no color, so translucent drawables are blitted directly (Tinkers `ToolBuildingCategory`).
  Side discovery: in 1.21.5 `blit` already ignored `setShaderColor`, so the Tinker Station's 82%/28% faded layout icon
  and slot backgrounds were drawn **opaque** (black silhouettes) — 1.21.8 restores the intended look.
- **⚠️ Text without alpha is invisible.** `drawString` returns early when the color's alpha is 0, so `0x404040`,
  `4210752` or a color read as `RRGGBB` from data draws nothing — no error. Opaque every literal (`0xFF404040`) and
  OR in alpha where colors come from data (Mantle `TextDataRenderer.legacyTextColor`, = 1.21.5 `Font.adjustColor`,
  used by book text and `AppearanceData.getCoverTextColor`). `drawString` is `void` and int-only now.
- **`Screen#renderWithTooltip` calls `renderBackground` *before* `render`** (1.21.5: `render` called it). Code that
  adjusted bounds inside `render` no longer covers `renderBg` — Mantle `MultiModuleScreen` wraps both in
  `withCorrectedBounds` (try/finally). NeoForge's `ContainerScreenEvent.Render.Background` now fires after it.
- **Tooltips are deferred:** `setTooltipForNextFrame(font, lines, positioner, x, y, focused)`. One tooltip per frame,
  **first wins unless `focused = true`** (focused replaces), and it is drawn at the end **without the pose** — pass
  screen coordinates (Mantle `BookElement.setPageTooltip` applies the page translation). Tinkers uses `focused = true`
  where 1.21.5 drew its tooltip over slot tooltips (policy in the `GuiUtil` javadoc). NeoForge's component tooltip
  gather/wrap path has no public focused variant, so those stay first-wins.
- Deferred tooltips only render while a screen is open → a HUD tooltip (Mantle gauge tooltip) is collected in the
  `RenderGuiLayerEvent` and drawn immediately in `RenderGuiEvent.Post` after `nextStratum()`.
- Mob-effect icons: the mob-effect atlas is gone → `Gui.getMobEffectSprite(Holder<MobEffect>)`, i.e. GUI sprites at
  **`textures/gui/sprites/mob_effect/<id>.png`** (Tinkers moved 28 PNGs; old paths render missing-texture).
- `InventoryScreen.renderEntityInInventory` takes a 4-int region; maps in a GUI go through `submitMapRenderState`.
- `Gui.leftHeight` is public in NeoForge 21.8 (Mantle's AT line is now redundant, harmless).
- Tinkers' tiled fluids (`GuiUtil.renderTiledTextureAtlas`, 13 callers) were immediate-mode buffers → now one
  `BlitRenderState` per tile with exact sub-UVs for partial tiles; `GuiUtil.renderFluidTank/renderTiledFluid/
  renderTiledTextureAtlas` take a `GuiGraphics`.

## Picture-in-picture — 3D in a GUI

- Anything 3D inside a GUI (entities, book structure previews, models) is a **`PictureInPictureRenderer<S>`** that renders
  into its own texture, blitted by the GUI. Register on NeoForge `RegisterPictureInPictureRenderersEvent`
  (`register(StateClass.class, bufferSource -> new Renderer(bufferSource))`) and submit with
  `graphics.submitPictureInPictureRenderState(state)`. NeoForge keeps a **renderer pool per state class**, so two previews
  on one screen get separate renderers. Template: vanilla `GuiEntityRenderer`.
- **⚠️ PiP state bounds are absolute screen coordinates and the pose is ignored.** Compute them with
  `graphics.pose().transformPosition(...)` and pass `graphics.peekScissorStack()`. Vanilla
  `submitEntityRenderState` follows the same rule while JEI 24 positions ingredients with `pose().translate(x, y)` →
  Mantle's JEI `EntityIngredientRenderer` drew entities at the top-left (or scissored away) until it switched to absolute
  coordinates under an identity pose (`renderEntityInInventoryFollowsAngle`).
- Mantle `StructureElement` now only submits a `StructureRenderState` (absolute bounds; the area is the circumscribed
  square so rotation never reallocates the texture); `StructurePiPRenderer` (`client/screen/book/element/pip/`) does the
  `collectParts` + `tesselateBlock` work, registered by Mantle's `ClientEvents`.
- Offscreen export (Mantle `BookCommand`) records into `new GuiGraphics(mc, GuiRenderState)` and draws with the game's own
  `GuiRenderer` (ATs on `GameRenderer.guiRenderer/guiRenderState/fogRenderer`), swapping window size and GUI scale and
  restoring them in `finally`.

## GUI item atlas — model identity

- **⚠️ 1.21.6+ draws GUI items once into an atlas keyed by `ItemStackRenderState.getModelIdentity()`.** Vanilla
  `BlockModelWrapper` appends itself; a custom `ItemModel` that appends nothing shares the empty identity with every other
  such item, and all of them show **whichever was drawn first** (the Tinker Station tabs showed an arrow instead of the
  table). Compiles clean, crashes nothing.
- Fix (Mantle `ModelHelper.addItemLayer`): `renderState.appendModelIdentityElement(extents)` with the **memoized
  per-variant extents supplier** (compares by identity → stable, unique key); for foil also `setAnimated()` + append
  `FoilType.STANDARD`; `setAnimated()` when a quad uses an animated sprite (`ModelHelper.hasAnimatedSprite`, computed once
  at bake). Every variant cache must therefore return the *same* supplier for the same look and a different one for a
  different look.
- A cache that never hits now also leaks atlas identities every frame: Tinkers' `FluidContainerModel` was keyed by
  `FluidStack` (no `equals`/`hashCode`) → keyed with `FluidStackLinkedSet.TYPE_AND_COMPONENTS`.
- Guard: uitest `dynamic_item_icons` asserts identities are non-empty, stable across frames and pairwise distinct.

## Serialization — `ValueInput` / `ValueOutput`

- `BlockEntity#loadAdditional(ValueInput)` / `saveAdditional(ValueOutput)`; `Entity#readAdditionalSaveData(ValueInput)` /
  `addAdditionalSaveData(ValueOutput)`; NeoForge `handleUpdateTag(ValueInput)` / `onDataPacket(Connection, ValueInput)`.
  `getUpdateTag(Provider)` and `saveWithoutMetadata/saveCustomOnly(Provider)` still return a `CompoundTag`.
- `ValueInput` has **no raw `CompoundTag` access**: `read(key, codec)`, `child/childOrEmpty`, `list[OrEmpty](key, codec)`,
  `get*Or`, Optional `getInt/getString/…`. Read an NBT blob with `read(key, CompoundTag.CODEC)`, write it with
  `store(key, CompoundTag.CODEC, tag)`.
- Bridge for packets, tests and legacy blobs: `TagValueOutput.createWithContext(reporter, provider)` /
  `TagValueInput.create(reporter, provider, tag)` inside a `ProblemReporter.ScopedCollector` (Mantle `MantleBlockEntity`,
  Tinkers `TagUtil.writeTag/readTag`).
- Removed: `ItemStack.parse/save` → `ItemStack.CODEC`/`OPTIONAL_CODEC` or `ItemStackWithSlot`; NeoForge
  `FluidStack.parse/save*` → `FluidStack.CODEC`/`OPTIONAL_CODEC`; `FluidTank.readFromNBT/writeToNBT` →
  `serialize/deserialize`; `INBTSerializable` → **`ValueIOSerializable`**; `Component.Serializer` →
  `ComponentSerialization.CODEC`.
- **NBT parity:** `TagValueOutput` + `store(key, CODEC, v)` uses the same codec and registry ops as 1.21.5's
  `ItemStack.save(provider)`, so saved worlds stay byte-compatible — **as long as you keep the old keys**. One shape change:
  `ItemStackWithSlot` writes `"Slot"` as an **unsigned byte** (old ints still read, but slots > 255 collapse into 0).
  Tinkers' largest handler is 256 slots (0–255), so it fits; the chest `Slot` went int → byte (backward-readable).
  NeoForge `ItemStackHandler` keeps `"Items"` + `"Size"`, `FluidTank` keeps `"Fluid"`.
- **⚠️ NeoForge 21.8 `ItemStackHandler.deserialize` no longer calls `onLoad()`** — Tinkers' `ScalingChestItemHandler`
  overrides `deserialize` to recompute its size (cast/part chests showed one slot after a reload).
- Watch shared constants: a deserialize into a `FluidStack.EMPTY` default can mutate the global empty stack.
- Thrown tools: since 1.20.5 vanilla stores the arrow pickup stack under **`"item"`**, not `"Trident"` — Tinkers'
  `ThrownTool` checked the old key, so a reloaded thrown tool never re-synced (fixed on all lines, see below).
- Mantle `NameableBlockEntity` still writes `CustomName` as a JSON string (old worlds load).
- Guard: Tinkers `SaveCompatGameTests` round-trips melter, casting, tables, part chest, thrown tool, arrow and shuriken
  through save → load with on-disk key/type checks against the 1.21.5 shapes, plus legacy shapes.

## Shaders & fog

- Uniforms are **std140 uniform blocks**: `#moj_import <minecraft:dynamictransforms.glsl>` (`ModelViewMat`,
  `ColorModulator`, `ModelOffset`, `TextureMat`), `<minecraft:projection.glsl>` (`ProjMat`), `<minecraft:fog.glsl>`
  (`apply_fog(...)`, `fog_spherical_distance`/`fog_cylindrical_distance`). Loose `uniform mat4 …` declarations and
  `FogShape` are gone; pipelines use `RenderPipelines.MATRICES_FOG_SNIPPET` (`MATRICES_COLOR_FOG_SNIPPET` removed).
  Custom core shaders **fail only at runtime** — Mantle's `fluid` and `block_fullbright` were rewritten after vanilla
  `core/terrain.vsh/.fsh` (`pos = Position + ModelOffset`, multiply by `ColorModulator`). `core/position_color_tex_lightmap`
  still exists.
- Fog: `FogParameters`/`FogMode`/`FogShape` removed → `fog.FogData` (environmental start/end, render distance, sky/cloud
  end; no shape) + `FogEnvironment`. NeoForge `IClientFluidTypeExtensions.modifyFogRender(Camera, @Nullable
  FogEnvironment, float renderDistance, float partialTick, FogData)` mutates in place (`void`).
- Mantle `FluidTexture`: `FogShape fogShape` → `boolean overrideFog`. **Rule on read: override iff the JSON `fog` object
  has `shape`, or both `start` and `end`** (strict 1.21.5 compatibility); `shape` is accepted and ignored
  (`FluidTextureManager` warns per file); datagen no longer writes it (Tinkers: 70 `fluid_texture` JSONs lost
  `fog.shape`). `Builder.fog(shape, start, end)` → `fog(start, end)`. `modifyFogRender` still only tightens the fog and
  clamps sky/cloud end like vanilla.

## Render & models (misc)

- **⚠️ NeoForge frustum-culls block entity renderers with the *renderer's* `getRenderBoundingBox(be)`** (default: one
  block), not the BE's. Big renderers vanish when their origin leaves the view (smeltery fluid disappeared with the
  controller off-screen — since 1.21.5). Tinkers' heating structure, channel, faucet and table renderers delegate to the
  BE's box.
- `BlockEntityRenderer#shouldRenderOffScreen()` lost its BE argument → Mantle's inventory renderers no longer override it
  (can't express "only when non-empty"); Tinkers' heating structure renderer returns `true`.
- `RenderType.translucent()` removed; `ItemBlockRenderTypes.setRenderLayer`, NeoForge `RenderTypeGroup` and
  `SimpleModelWrapper` take a **`ChunkSectionLayer`** (Mantle `ElementModelData.blockRenderType()` returns one).
- `RenderLevelStageEvent.Stage` → sub-events (`RenderLevelStageEvent.AfterTripwireBlocks`, …).
- `StandaloneModelBaker` removed → `SimpleUnbakedStandaloneModel.blockStateModel(id)` (Tinkers item frames);
  `SkullSpecialRenderer(model, 0, renderType)` constructor; `SpecialModelRenderer#getExtents`.
- Blaze3d buffers: `BufferType/BufferUsage` → `GpuBuffer.USAGE_*` flags (NeoForge validates them), `ReadView` →
  `MappedView`, `readBuffer` → `mapBuffer`.
- **⚠️ GPU readback is async.** With `GL_ARB_buffer_storage` a `USAGE_MAP_READ` buffer is persistently mapped and
  `mapBuffer` only slices the pointer, so reading right after `copyTextureToBuffer` returns stale driver memory (often the
  *previous* frame). Mantle `RenderTargetCapture`: client-mapped-buffer barrier, `encoder.createFence()`, `glFlush`, then
  a bounded `awaitCompletion` loop before `mapBuffer`.

## Datagen (tags)

- Vanilla `ItemTagsProvider` → NeoForge **`BlockTagCopyingItemTagProvider`** (`copy(blockTag, itemTag)`, takes the block
  `TagLookup` future); key-based registries (enchantments) → `KeyTagProvider`.
- Appenders are `TagAppender<E, T>`: `addOptional(RL)`, `addOptionalTag(RL)`, intrinsic `add(ResourceKey)`,
  `remove(RL)` and `getInternalBuilder` are gone → `add(TagEntry.optionalElement(rl) / optionalTag(rl) /
  element(rl))` produce identical `TagBuilder` entries. Kept: `replace`, `remove(E | TagKey)`, `addTags`,
  `addOptionalTags`.
- Diff the regenerated tags: here they came out **byte-identical** in both repos. The other diffs were structure `.nbt`
  `DataVersion` (4325 → 4440) and the dropped `fog.shape`. The `runData`/`runServerData` purge-and-restore procedure from
  M1 still applies.

## Networking, events & mechanical renames

- `PacketDistributor.sendToServer` → **client-only `ClientPacketDistributor.sendToServer`**. Mantle `NetworkWrapper`
  keeps it in a nested holder so a dedicated server never loads the class; `NetworkWrapper.sendToServer` is unchanged
  for callers.
- **`@EventBusSubscriber(bus = …)` is removed** (FML 9), not deprecated — drop the attribute, the bus is inferred from the
  event type (24 Tinkers files).
- `FriendlyByteBuf.readJsonWithCodec` → `readLenientJsonWithCodec`; `ServerPlayer#serverLevel()` and
  `Entity#getCommandSenderWorld()` → `level()`; `DataVersion#getVersion()` → `version()` (+ `WorldVersion` record getters);
  `ProjectileUtil.getEntityHitResult` gains an inflation argument; command suggestions use
  `suggestRegistryElements(HolderLookup, type, builder)`.
- Test fakes: `Player(Level, GameProfile)`; FML's `IModInfo` lost `setSecurityStatus` (drop the override).

## Recipes & network codecs — runtime lessons

- **Singleplayer never serializes packets.** The integrated server hands the client the same objects, so a broken
  `STREAM_CODEC` is invisible in every client test. Tinkers' gametest `synced_recipes_stream_codec_round_trip` encodes →
  decodes → re-encodes every synced recipe (3067) with `RecipeHolder.STREAM_CODEC` and requires byte equality — it found
  two Mantle bugs on its first run:
  - compound `FluidIngredient.getAllFluids()` (the network list) flattened children through `getFluids()` (the display
    list, which filters flowing fluids) → the client copy no longer matched flowing fluids (317 recipes);
  - `MapLoadable` built maps with `Map.copyOf`, whose iteration order is randomized per JVM → intermittent re-encode
    mismatch. Now an unmodifiable `LinkedHashMap` (keeps JSON/network order).
- **The client only receives the recipe types requested in `OnDatapackSyncEvent#sendRecipes`** (since 1.21.4). Tinkers
  lists them in `RecipeLookupPopulator.CLIENT_SYNCED_TYPES`; alloying, entity melting and severing were missing, so their
  JEI categories were empty. Any type read client-side (JEI included) must be in that list.
- **`RecipeMap.getRecipesFor` (and `RecipeManager#getRecipeFor` since 1.21) return nothing when `RecipeInput#isEmpty()`**,
  i.e. all item slots empty — which is exactly castless casting (the fluid is the input). Tinkers
  `TinkerRecipeAccess.getRecipeFor` filters `byType(type)` by each recipe's `matches`.
- **`minecraft:max_damage` is `ExtraCodecs.POSITIVE_INT`, validated on encode.** Tinkers marked built tools with
  `max_damage = -1`; `ItemStack.CODEC` failed, and every built tool vanished from inventories, containers and entities on
  save (1.21.4+). The marker is `1`; the real value comes from the `getMaxDamage` overrides. Round-trip anything you put in
  a vanilla component.
- Check the client log for **JEI plugin errors**: `MeltingFuelHandler` sorted the immutable `Stream#toList()` JEI passed,
  the exception aborted `registerRecipes`, and every category registered after the fuels was missing — since 1.21.4,
  with every uitest `"ok"`. `MoldingRecipeCategory` NPE'd on pattern-less recipes (null since 1.21.4) and JEI silently
  dropped them as broken.
- Mantle `/mantle sources data recipes` looked in `recipes/` (1.21 renamed the folder to `recipe/`).

## Verification lessons

- **A uitest `"ok"` can be a wrong picture.** The first M4 run reported 16/16 ok while every PNG held the *previous*
  scenario's frame (the async readback above). The real gate was a **reference run of the previous milestone** (1.21.5
  tags checked out in throwaway worktrees, same suite) and a side-by-side review of every PNG pair. That review found the
  GUI atlas identity bug and the Tinker Station alpha difference.
- Round-trip save gametests found shipped data-loss bugs (built tools, modifier inventories) that no compile, unit test
  or singleplayer session showed.
- **uitest needs an unlocked screen:** while the Windows session is locked, GL window creation fails in `atio6axx.dll`
  (AMD driver) at `glfwCreateWindow`. Seven attempts died this way; they all passed once the screen was unlocked. Not a
  flake — don't retry in a loop.
- Sweep for the silent patterns on every port: color literals without alpha, and Optional getters (`ValueInput` too)
  passed into `Object` parameters (M3 lesson). Both sweeps were clean at the end of M4.

## Known issues (as of M4)

- **Stackable + damageable tools fail `ItemStack.validateStrict`.** Built daggers (`stacksTo(2)`), arrows and shurikens
  are damageable and stackable; vanilla rejects that combination ("cannot be both damageable and stackable"), so the
  creative-slot packet would disconnect a creative player moving one. Present since 1.21.4. Decision (2026-11-18):
  document, investigate later — no M4 code change. Saving is not affected (the dagger `ItemStack.CODEC` round-trip
  gametest passes); other `validateStrict` call sites have not been audited.
- Pre-existing, not M4 regressions (follow-ups):
  - fluid buckets / copper cans render as a full fluid square — `MantleItemLayerModel.getMaskedQuadsForSprite` leaves the
    front/back quads unmasked (since 1.21.4);
  - the legacy `tconstruct:trim` modifier model is not re-registered (`PORT 1.21.4` breadcrumb in `ToolClientEvents`), and
    the generated `armor_trims` atlas still uses the pre-1.21.4 `trims/models/armor/*` paths;
  - `MaterialBlockModel`'s item-side variant map (`ConcurrentHashMap`) is unbounded;
  - `casting_pour` shows no fluid stream at capture time (same on 1.21.5).
- Immersive Engineering and JSON Things compat stay excluded (no 1.21.8 builds).
- 12 lustrous modifiers still need a mod providing `c:ores/<metal>` item tags (unchanged since M1).
