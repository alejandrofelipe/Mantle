# Migration gotchas: 1.21.8 → 1.21.10 (roadmap M5)

Companion to [`1.21.5-to-1.21.8.md`](1.21.5-to-1.21.8.md). Target: **MC 1.21.10 / NeoForge 21.10.64**, Parchment
`1.21.10 / 2025.10.12`, JEI `26.3.0.31`; 1.21.9 folded in. Branch `1.21.10` in both repos. Released 2026-11-25 as
Mantle `1.16` / Tinkers `3.15.0` (tags `v1.21.10-1.16` / `v1.21.10-3.15.0`). Plan: `tinkers/docs/superpowers/plans/2026-11-23-m5-1.21.10-port.md`.

Practically every break comes from 1.21.9; the 1.21.10 primer only adds `BlockBehaviour#entityInside(…, boolean
intersects)` and `HangingEntity#getPopBox`. The compiler found 100 errors in Mantle (M4: 102) and 594 in Tinkers (M4:
546), half of them the mechanical `isClientSide()` rename. The real cost was the **NeoForge transfer API rework** (done
twice: a minimal step to compile, then a full migration), **two-phase rendering** and **event-based input**, both of
which break silently.

## Target choice & toolchain

- NeoForge **21.9 never left beta** and **JEI abandoned 1.21.9** → 1.21.10 is the first stable, JEI-supported step (same
  pattern as M1 skipping 1.21.2/1.21.3 and M4 skipping 1.21.6/1.21.7).
- Toolchain unchanged: NeoGradle **7.1.39** + Gradle **9.2.1**, Java 21. The NF 21.10.57+ binpatch tooling change does not
  affect NeoGradle 7.1.39 userdev (setup, decompile, recompile and `compileJava` all ran).
- Pins: JEI `26.3.0.31` (two majors up, see [Compat](#compat-jei-26-crafting-tweaks-json-things)), Crafting Tweaks
  `21.10.1+1.21.10` + Balm `21.10.11+1.21.10` (pulls `kuma-api-neoforge` at runtime), **JSON Things `0.16.0` re-added**
  (excluded since 1.21.4). Immersive Engineering stays excluded (1.21.1 only).

## Transfer API rework (the biggest wall)

NeoForge 21.9 replaced the item/fluid/energy capability API.

- New capabilities: `Capabilities.Fluid.{BLOCK, ENTITY, ITEM}` of `ResourceHandler<FluidResource>`,
  `Capabilities.Item.{BLOCK, ENTITY, ENTITY_AUTOMATION, ITEM}` of `ResourceHandler<ItemResource>`,
  `Capabilities.Energy.{BLOCK, ENTITY, ITEM}` of `EnergyHandler`. Item capabilities take an **`ItemAccess`** context
  (`ICapabilityProvider<ItemStack, ItemAccess, T>`); `RegisterCapabilitiesEvent` is unchanged.
- **⚠️ The old `Capabilities.FluidHandler`/`ItemHandler`/`EnergyStorage` classes are removed**, not deprecated, so every
  registration and lookup must move at once. The legacy interfaces (`IFluidHandler`, `IFluidHandlerItem`,
  `IItemHandler(Modifiable)`, `IEnergyStorage`, `FluidTank`, `ItemStackHandler`, `fluids.FluidUtil`, `SlotItemHandler`,
  `items.wrapper.*`, `EmptyFluidHandler`) are still there, `@Deprecated(forRemoval = true)` (removed in NeoForge 26.3).
- **⚠️ NeoForge only bridges new → legacy** (`IFluidHandler.of(ResourceHandler)`, `IItemHandler.of`, `IEnergyStorage.of`,
  `FluidResourceHandlerItemAdapter`). There is **no legacy → new adapter**, so a handler you *register* must be native.
- `ResourceHandler<T>`: `size()`, `getResource(i)`, `getAmountAsLong/AsInt(i)`, `getCapacityAsLong/AsInt(i, resource)`,
  `isValid(i, resource)`, `insert/extract(i, resource, amount, tx)` (+ index-free defaults). Changes happen inside a
  **transaction**: `Transaction.openRoot()` / `Transaction.open(ctx)`, `commit()`, `close()` (aborts if not committed).
  Simulate = open, act, close without commit. Building blocks: `SnapshotJournal<T>` (`createSnapshot`,
  `revertToSnapshot`, `onRootCommit`), `RootCommitJournal`, `StacksResourceHandler`, `ItemStacksResourceHandler`,
  `ItemStackResourceHandler`, `FluidStacksResourceHandler`, `ResourceHandlerUtil` (`move`, `moveFirst`,
  `findExtractableResource`, `insertStacking`, …), `transfer.fluid.FluidUtil`, `VanillaContainerWrapper`,
  `WorldlyContainerWrapper`, `PlayerInventoryWrapper`, `ResourceHandlerSlot`, `EmptyResourceHandler`.

### Our two steps

1. **Step 1 (compile):** every handler we register was ported natively to `ResourceHandler`/`EnergyHandler` and registered
   on the new capabilities; consumer code stayed on the legacy interfaces and reached other blocks through the new → legacy
   bridges (Mantle `TransferHelper.getLegacy*`/`asLegacy*`). No throwaway legacy → new adapter with approximate
   transaction semantics.
2. **Step 2 (full migration, before NeoForge 26.3 removes the legacy API):** every consumer moved to the native API, then
   the bridges were deleted. **0 transfer `[removal]` warnings** and zero code references to the legacy symbols in both
   repos (Tinkers had 713 references in 123 files).

### Mapping (legacy → native)

- `IFluidHandler`/`IFluidHandlerItem` → `ResourceHandler<FluidResource>` (+ `ItemAccess` for items);
  `fill/drain(…, FluidAction)` → `insert/extract(resource, amount, tx)`; `drain(int)` "first fluid" →
  `ResourceHandlerUtil.findExtractableResource` + `extract` (Mantle `FluidTransferHelper.getDrainableFluid`);
  `getFluidInTank/getTankCapacity` → `transfer.fluid.FluidUtil.getStack(handler, i)` / `getCapacityAsInt(i,
  FluidResource.EMPTY)` (what the bridge reported); `IFluidHandlerItem#getContainer()` → the stack left in an isolated slot.
- `IItemHandler(Modifiable)` → `ResourceHandler<ItemResource>`; `ItemStackHandler` → `StacksResourceHandler` subclass or a
  journal over the owner's list; `SlotItemHandler` → `ResourceHandlerSlot`; `EmptyItemHandler` →
  `EmptyResourceHandler.instance()`; `InvWrapper`/`SidedInvWrapper` → `VanillaContainerWrapper.of` /
  `WorldlyContainerWrapper`; `ItemHandlerHelper.giveItemToPlayer` → `PlayerInventoryWrapper` (Tinkers wraps it in
  `TransferUtil.giveItemToPlayer`, same drop/sound behavior).
- `IEnergyStorage` → `EnergyHandler`; `fluids.FluidUtil` → `transfer.fluid.FluidUtil`.
- Tinkers' own APIs that only used `IFluidHandler.FluidAction` as a simulate flag (tool tank hooks, the fluid effect API)
  now take Tinkers' `library.fluid.FluidAction` enum (import-only change, no data change).

### Keep the saved shapes — override serialization

- **⚠️ The native base classes write different NBT keys:** `StacksResourceHandler` (and the fluid/item subclasses) writes a
  `stacks` list, `ItemStackResourceHandler` a `stack`. The legacy classes wrote `FluidTank` → **`Fluid`**
  (`FluidStack.CODEC`, nothing when empty) and `ItemStackHandler` → **`Items`** (`ItemStackWithSlot` list, empty slots
  skipped) + **`Size`**. Never (de)serialize a native base class through its own `serialize`/`deserialize`; override them
  with the legacy keys.
- Mantle **`transfer.SingleFluidTank`** replaces `FluidTank`: legacy getters/setters (`getFluid/setFluid/getCapacity/
  setValidator/isFluidValid/getSpace`), a private `SnapshotJournal<FluidStack>`, `onRootCommit(original)` (default:
  `onContentsChanged()` if the fluid changed) and `serialize/deserialize` writing `Fluid` exactly like the legacy tank.
  `setFluid` stays a **silent** setter like the legacy tank (packets, NBT load and tank items relied on it).
- Mantle **`SingleItemHandler`** is native: a private `ItemStackResourceHandler` journal, `setStackSilently` during
  transactions, the final stack replayed once through the public `setStack` on root commit (subclass side effects),
  capacity capped at the item's max stack size, `writeToNBT/readFromNBT` unchanged (`ItemStack.CODEC`, `{}` when empty).
- Tinkers chests: `ChestItemHandler` writes the exact `ItemStackHandler` shape. Unit tests compare `SingleFluidTank` and
  `ChestItemHandler` against **byte-level fixtures** of the legacy output (proven equal to the legacy classes before they
  were dropped), so the check survives NeoForge 26.3.

### Transaction pitfalls

- **Side effects only on root commit.** Simulated or aborted transfers must leave no trace: journal the state, and notify
  the owner (setChanged, sync packets, recipe start, comparator) from `onRootCommit`. Tinkers' casting table sizes the cast
  with a simulated recipe lookup during the fill and starts the recipe on commit; draining to empty resets on commit.
- **⚠️ Never open a root transaction inside a transaction.** `Transaction.openRoot()` throws when one is open on the thread
  — and the legacy bridges' `fill`/`drain`/`insertItem` open a root. Code reachable from inside a native
  `insert`/`extract` (recipe matching, forwarding to a neighbor) must use the native lookups with the given transaction, or
  `TransferHelper.openNestedOrRoot()`. Mantle `FluidContainerIngredient` crashed a native casting fill this way (fixed).
- **⚠️ `CLOSING` lifecycle:** journal revert/release callbacks run while the transaction closes; then
  `TransferHelper.isTransactionOpen()` is false yet nothing can be opened (`openNestedOrRoot` throws a descriptive
  `IllegalStateException`). Listeners that may run during a revert must only invalidate state (Tinkers
  `IMultitankListChange`).
- **`VanillaContainerWrapper` calls `Container#setItem` during the transaction** (reverted on abort), so `setItem`
  overrides with side effects also fire on simulations. Tinkers' casting blocks use their own native handler instead.
- **Interaction helpers open their own root.** Mantle's `FluidTransferHelper.interactWith*` run one root transaction per
  interaction, committed only when fluid moved — don't call them inside a transaction. A nested transaction opened from a
  root-commit callback does work (the casting tank processes an inserted bucket that way).
- **Overload ambiguity while both APIs coexist:** a handler implementing both `IFluidHandler` and
  `ResourceHandler<FluidResource>` made same-arity calls ambiguous; pick the native overload explicitly until the legacy
  ones are gone.
- **Cached views go stale after an abort:** Tinkers' duct mapping is computed fresh while a transaction is open, and the
  smeltery tank reruns its list listeners when a revert changes the layout.

### Item semantics

- An item capability's amounts are **totals over the accessed stack**. For per-container work (one bucket of a stack of
  3), isolate a one-item copy: Mantle `TransferHelper.isolate(stack[, count])` → `access(slot)` /
  `getFluidResourceHandler(slot)`, result via `getStack(slot)`. The passed stack is never mutated.
- Single-slot capacities are capped at the max stack size (legacy over-stacked unstackables); Tinkers tank items store a
  per-item tank (legacy wrote the stack total into each item). Inserting into a tool inventory slot holding the same item
  with other components now inserts nothing (native contract; legacy lost the inserted components).

### Menus and slots

- NeoForge `ResourceHandlerSlot` sits on a dummy container at index 0. Code reading `getSlotIndex()`/`getContainerSlot()`
  needs the handler index: Tinkers `ModifiableItemHandlerSlot` reports it (and guards it against a shrinking handler —
  the smeltery menu crashed the server when the structure shrank).
- **⚠️ `StackCopySlot` write-back:** `ResourceHandlerSlot#getItem` returns a copy, and `setChanged` writes back only the
  copy from the **latest** `getItem()` call. Vanilla calls `getItem()` again before `overrideOtherStackedOnMe`, so an
  in-place change of the stack it was handed is silently dropped (a bucket clicked onto a tank item in a Tinkers chest
  emptied and the fluid was lost). Write the slot stack back explicitly.
- **Transactional slots over foreign handlers** (a side inventory exposing only the native capability): the slot can only
  set a stack by extracting/inserting the difference, so vanilla's click logic must be bounded by simulation — `mayPlace`,
  `getMaxStackSize(stack)`, `mayPickup` (whole stack extractable) and `tryRemove` measure the change of the slot itself
  (handlers may put items elsewhere or void them). A **safety net** at the final write: a set the handler refuses gives
  whatever vanilla already took back to the player (`TransferUtil.giveItemToPlayer`, server side only); plain `set` never
  refunds. Mantle `BaseContainerMenu.mergeItemStackRefill/Move` now honor `mayPlace` and shrink the source only by what the
  slot then holds.
  - **The final write must never trust the simulation** (a handler can contradict it). `StackCopySlot#remove` is final and
    ignores a refused set of the remainder, so a transactional `tryRemove` must not call `super`: set the remainder first
    (all or nothing), hand out only what left the slot. A refused swap/clear has already handed the old stack out — empty
    the slot, and if even that is refused take the copy back from the cursor/inventory (never ignore the result). A
    same-item number-key swap from a smaller hotbar stack is a swap (new count < old), not "old + difference".
  - **Merges vs consuming containers:** a container may consume/transform the item in `setItem` (casting tank: input
    processed into output, input empty again), which looks like a refusal from the slot alone. Mantle's `acceptedBySlot`
    compares the whole menu before/after (other slot changed or slot holds something else → taken; slot unchanged →
    refused; same item → its increase), and reads the slot before `setChanged` so a `StackCopySlot` does not write its
    stale copy back (that re-credited the bucket in the casting tank input).

## Two-phase rendering

1.21.9 split every world renderer into **extract** (read the game state into a render state) and **submit** (queue draws
on a `SubmitNodeCollector`); the feature dispatcher owns the buffers and draws later in the frame.

- `BlockEntityRenderer<T, S extends BlockEntityRenderState>`: `createRenderState()`, `extractRenderState(be, state,
  partialTick, cameraPos, crumblingOverlay)` (call super), `submit(state, pose, collector, cameraState)`. Same split for
  `EntityRenderer<T, S>`, `RenderLayer#submit(…)`, special item models.
- **Render states hold copies only** — no block entity, level or live `FluidStack`. Lambdas passed to the collector run
  later in the frame, so pass state-owned copies. `BlockEntityRenderDispatcher` creates a fresh state per block entity per
  frame (nothing to reuse inside it; a renderer-level pool would be shared by every instance).
- Custom vertex geometry (fluid cuboids) → **`collector.submitCustomGeometry(pose, renderType, (pose, vertexConsumer) ->
  …)`**. Mantle `FluidRenderer` has `PoseStack.Pose` overloads plus `submitCuboids`/`submitScaledCuboid`; the immediate
  `renderScaledCuboid(PoseStack, MultiBufferSource, …)` is deprecated.
- **Items in the world:** `ItemRenderer.renderStatic` is gone → `ItemModelResolver` fills an `ItemStackRenderState` at
  extract, `state.submit(…)` at submit (Mantle `RenderingHelper.extractItem/submitItem`, `InventoryRenderState`).
  `ItemModel#update` takes an `ItemOwner` instead of a `LivingEntity`.
- **Casting fade:** wrapping a `MultiBufferSource` to tint/fade the recipe output is impossible now. Tinkers'
  `TintedItemRenderState` edits the resolved layers after extraction (extra tint index for untinted quads, cooling tint +
  alpha multiplied into every tint, translucent render type while alpha < 255). Special-renderer layers draw opaque.
- **⚠️ Atlases:** `ModelManager.getAtlas`/`Minecraft.getTextureAtlas` and `Material#sprite()` are gone →
  `Minecraft.getInstance().getAtlasManager().getAtlasOrThrow(id)` / `.get(material)`. `getAtlasOrThrow` takes the atlas
  **id** (`AtlasIds.BLOCKS` = `minecraft:blocks`), **not** `TextureAtlas.LOCATION_BLOCKS` — that compiles and throws
  `Invalid atlas id` at runtime. Animation flag → `sprite.contents().isAnimated()`.
- **Block outline:** NeoForge `RenderHighlightEvent` is gone → `ExtractBlockOutlineRenderStateEvent` (collect positions
  and shapes at extract, `addCustomRenderer(CustomBlockOutlineRenderer)`; return `false` to keep the vanilla outline).
  Tinkers' AOE outline draws with `RenderType.lines()`, camera-relative via `levelState.cameraRenderState.pos`, and follows
  the high-contrast option. `RenderLevelStageEvent` sub-events still fire (the extra-block breaking overlay is unchanged).
- Particles: `TextureSheetParticle` merged into `SingleQuadParticle`; `ParticleProvider#createParticle(…, RandomSource)`.
  Skulls: `CreateSkullModels#registerSkullModel(…, texture)` (throws on duplicates — drop manual `SKIN_BY_TYPE.put`).
  Fishing lines are `RenderType.lines()` segments like vanilla.
- The M4 frustum fix survives: renderers still delegate `getRenderBoundingBox` to the block entity.

## Event-based input

- `GuiEventListener`: `mouseClicked(MouseButtonEvent, boolean doubleClick)`, `mouseReleased(MouseButtonEvent)`,
  `mouseDragged(MouseButtonEvent, dx, dy)`, `keyPressed/keyReleased(KeyEvent)`, `charTyped(CharacterEvent)`;
  `mouseScrolled` unchanged. Widgets: `onClick(MouseButtonEvent, boolean)`, `onRelease`, `onDrag`,
  `isValidClickButton(MouseButtonInfo)`, `AbstractButton#onPress(InputWithModifiers)`. Build synthetic events with
  `new MouseButtonEvent(x, y, new MouseButtonInfo(button, 0))`.
- **⚠️ Silent trap:** a method keeping the old `(double, double, int)` signature without `@Override` compiles and is never
  called. Port a screen hierarchy **top-down** and re-sweep: `TinkerStationScreen`/`ModifierWorktableScreen` compiled only
  because their parent still had the old signatures, so they were not in the error list.
- Forward `doubleClick` to `super` (vanilla takes the double-click decision from `MouseHandler`).
- `Screen.hasShiftDown()` and friends (static) are gone → instance `Minecraft#hasShiftDown/hasControlDown/hasAltDown()` or
  the event's modifiers. They poll the real GLFW key state, so synthetic `KeyEvent`s don't change them (manual check
  only). `Minecraft.ON_OSX` → `InputQuirks.ON_OSX`.
- Mantle adapts at the vanilla boundary: `MultiModuleScreen`/`BookScreen` take the events and unpack them;
  `ModuleScreen.handleMouse*` and `BookElement.mouse*` keep `(x, y, button)`. `BookScreen` hit-tests with the real cursor,
  so synthetic book clicks must move the cursor (Mantle `UiTestContext.moveMouse`).

## Data components & tool data

- **`CustomData#getUnsafe` is removed.** Tinkers' `ToolStack` reads *and mutates* the live tag and checks its identity,
  so `copyTag()` would silently break write-through → AT `public CustomData tag`.
- **⚠️ `Item#verifyComponentsAfterLoad` is removed with no replacement.** Tools used it to resolve material redirects,
  rebuild stats after datapack changes and sync the 1.21.5 shield components. Removing the `@Override` would silently drop
  all of that. Tinkers' replacement is **lazy verification on read** (`ToolDataVerifier`):
  - no stamp in the data (a per-generation key would stop stackable tools and parts from stacking with fresh ones and
    resync every inventory once per session); instead a weak identity map `CustomData` → verified result;
  - a new generation starts on `TagsUpdatedEvent` with cause `SERVER_DATA_LOAD` (after every reload listener), so stacks
    are verified once per session and again after `/reload`;
  - `ToolStack.from/copyFrom` verify **only on the logical server thread**; an instance already verified hands its result
    to other holders (as their own copy, no recompute); an unknown instance is marked first (no retry loop), verified on a
    copy under a recursion guard, and replaced only if the tag changed;
  - clients resolve material redirects in memory only; stats of a stack the server never read may show stale — accepted.
- **⚠️ Copy-sharing regression (1.21.9).** The removed hook ran in the private `ItemStack(ItemLike, int,
  PatchedDataComponentMap)` constructor (used by `copy()`, decode, item resources) and gave every copy a fresh tag. Without
  it copies share the `CustomData` instance, and in-place writes leak into them — e.g. the `LivingEntity` equipment
  snapshot (`lastEquipmentItems`) changed with the tool, so breaking a tool fired no equipment change and kept its
  attributes. **Armor, arrows and shurikens had this since 1.21.1** (they never overrode the hook).
- Fix = ownership rules + **Tinkers' first mixin** (`ItemStackMixin`, `tconstruct.mixins.json` declared in
  `neoforge.mods.toml`), with `ToolDataOwnership` (weak identity map instance → owning stack):
  - the mixin runs at the end of that constructor for `IModifiable` items: if **another stack owns** the source instance,
    the new stack gets its own deep copy and the original stays the owner (long-lived bound `ToolStack`s — tool container
    menus, bows, thrown tools — keep writing to the right stack; releasing ownership instead broke them);
  - `ToolStack.from(stack)`/`refreshTag` give the stack its own copy before binding unless it owns the instance;
    `setStackTag` claims its fresh instance; unowned data (decoded, never bound) stays shared until a holder binds;
  - ownership is only taken on the logical server thread or the client main thread; elsewhere (background tooltip search,
    workers) a detached copy is bound and never claimed;
  - **not covered:** component patches taken without copying the stack (`getComponentsPatch`, `applyComponents`).
- Guard: gametests compare copies after modifying/breaking the original, the equipment-change detection, and a tool
  container tank click after the opening copy + an inventory tick.
- `DataComponents.ENTITY_DATA`/`BLOCK_ENTITY_DATA` hold **`TypedEntityData`** (`of(type, tag)`, `loadInto`,
  `copyTagWithoutId`); `SpawnEggItem#getType(stack)` is nullable (the type lives on `ENTITY_DATA`). Player heads:
  `new ResolvableProfile(gameProfile)` → `ResolvableProfile.createResolved(gameProfile)`.

## Mechanical & core changes

- `Level#isClientSide` field is private → **`isClientSide()`** (scripted: `\.isClientSide\b(?!\()`, 203 Tinkers sites);
  `Properties#noCollission()` → `noCollision()`; `Items/Blocks.CHAIN` → `IRON_CHAIN` (changes item ids in generated
  recipes).
- `Entity#getServer()` removed → `entity.level().getServer()` (nullable).
- Reload listeners: `reload(SharedState, Executor, PreparationBarrier, Executor)`; resource manager from
  `sharedState.resourceManager()`. Mantle's `IEarlyReloadListener`/`IEarlySafeManagerReloadListener` adapt once, their own
  callbacks are unchanged.
- FML 10: `FMLEnvironment.dist/production` fields → `getDist()`/`isProduction()`; `FMLLoader.getCurrent()` instance API.
  Unit tests must mock both (`SharedConstants.<clinit>` calls `isProduction()`, `FeatureFlagLoader` calls
  `FMLLoader.getCurrent().getLoadingModList()`).
- `KeyMapping(String, int, KeyMapping.Category)`; register the category with `RegisterKeyMappingsEvent#registerCategory`.
  Category `tconstruct:main` → lang key `key.category.tconstruct.main`.
- `entityInside(…, InsideBlockEffectApplier, boolean intersects)` (1.21.10). Tinkers ignores `intersects` (1.21.8 already
  fired for swept blocks).
- `Container#startOpen/stopOpen(ContainerUser)`; `WritableLevelData#setSpawn(RespawnData)`,
  `Level#getRespawnData/setRespawnData` and `getWorldBorder()` (world border moved off `Level`; fake levels implement
  them); `Level#explode` gained a block-particles parameter; `getAnalogOutputSignal(…, Direction)`;
  `onDestroyedByPlayer(…, ItemStack, …)`; `Minecraft.cameraEntity` private → `getCameraEntity()`.
- Creeper skull API removed (heads come from the `charged_creeper` loot table) → AT `public Creeper droppedSkulls`; vanilla
  sets it before `LivingDropsEvent`, so `isPowered() && !droppedSkulls` ≡ the old `canDropMobsSkull()`.
- `startRiding(…, true, true)` keeps the `ENTITY_MOUNT` game event (1.21.9 moved it behind `sendGameEvent`).

## Serialization & client sync

- **⚠️ NeoForge `ValueInput#keySet()` throws `NoSuchElementException` on the shared empty input** that
  `childOrEmpty` returns for a missing tag. Tinkers' empty tanks save no `tank` tag, so the update packet of an empty
  structure tank disconnected the client and its load failed — shipped in 1.21.8 (fixed, backported).
- **Load what the save omits.** Many block entities only applied keys that are present, while their save leaves them out
  when empty; a client copy receiving an update tag kept the old contents. Mantle `NameableBlockEntity` (name),
  `DefaultRetexturedBlockEntity` (texture) and `InventoryBlockEntity#readInventory` (a present `Items` list now clears
  unlisted slots; no list leaves the inventory untouched) reset like vanilla; 26 Tinkers blocks were affected.
- Guard: Tinkers `BlockEntityRoundTripGameTests` — every block of every Tinkers block entity type, empty, filled and
  filled → empty: save, load into a fresh instance, save again (identical), then update tag + data packet into a fresh
  client copy that must produce the same update tag; formed smeltery/foundry, fueled melter/alloyer and a pouring faucet
  included.

## Shaders

- **⚠️ Vanilla 1.21.9 removed `core/position_color_tex_lightmap`.** A pipeline using it fails to compile, and
  `ShaderManager.apply` throws when any registered pipeline fails, so the shader source cache stays empty — the client
  crashed at the first GUI frame with `Pipeline contains invalid shader program`, blaming `gui_textured` (a cascade).
  Mantle ships the 1.21.8 shader as `mantle:core/fluid_no_fog` for `MantleShaders.FLUID_NO_FOG`. Mantle's `fluid` and
  `block_fullbright` compile unchanged.

## Datagen

- **Datagen through the cache.** The client and server runs purged each other's outputs (the vanilla `HashCache` deletes
  every file no provider of the run produced), and texture generators writing past the cache were purged by their own run.
  Mantle `DatagenCacheKeeper.keepOtherRunOutputs(event)` (lowest priority, both `GatherDataEvent` sides) registers every
  provider with a `.cache` file the run lacks as a not-run provider, so the cache keeps its files;
  `GenericTextureGenerator#saveImage` writes through `CachedOutput#writeIfNeeded` (AT on `NativeImage#writeToChannel`).
  `runData`, `runServerData`, `runServerData`, `runData` → 0 written, 0 removed. Needs the local `.cache` (Tinkers does
  not commit it: run both once on a fresh clone); multi-mod `--flat` runs are left alone.
- **Spawn egg textures:** Tinkers egg models parented `minecraft:item/template_spawn_egg` (gone since 1.21.5).
  `SpawnEggTextureProvider` now bakes the pre-1.21.5 look (template base × primary, overlay × secondary) from
  `SpawnEggColors`. The template layers are Mojang's, read from the 1.21.4 client jar (SHA-1 `a7e5a602…`): found in the
  NeoGradle/ForgeGradle caches, the official launcher or Prism, `-PspawnEggTemplateJar`, or **downloaded by Gradle** from
  `piston-data.mojang.com` into `caches/modules-2` (SHA-1 + size checked). Not committed to the repo.
- Pack metadata: `pack.mcmeta` uses `min_format`/`max_format` (`PackFormat(major, minor)`). One mod `pack.mcmeta` serves the
  client (format 69) and server (88) packs; a `min_format` ≤ 81 needs `supported_formats` on the server, which the client
  rejects above 64 → Tinkers declares `min_format`/`max_format` 88. NeoForge ignores the range of mod packs. Mantle keeps
  `pack_format` 4 (logs nothing). `GeneratePackHelper` writes `packVersion(type).minorRange()` like `/datapack create`.
- Regen diffs: `minecraft:chain` → `minecraft:iron_chain` (8 recipes), structure `.nbt` `DataVersion` 4440 → 4556; tags,
  loot, models byte-identical. No copper tool tier adopted.
- `GreyToColorMapping.scaleColor`: M1's ABGR → ARGB port moved upstream's `int` overflow from blue to red, so 129 part
  textures regenerated a few pixels off. Now reproduces upstream exactly — **including** the blue-channel overflow (parity
  decision: 3 pixels in 3 maille sprites differ from the "correct" math).

## Compat (JEI 26, Crafting Tweaks, JSON Things)

- **JEI 26.3:** deprecated-for-removal renames, all behavior-neutral delegates (`javap -c`): `RecipeType` →
  `IRecipeType` (`IRecipeType.create`), `addRecipeCatalyst(stack, types…)` → `addCraftingStation(type, …)` per type,
  `addIngredient(type, v)`/`addIngredients(Ingredient)`/`addItemStack` → `add(…)`, `ITooltipBuilder#toLegacyToComponents/
  removeAll` → `getLines()`, `IRecipeCategory#getBackground` → `getWidth/getHeight` + draw it in `draw()`,
  `getTooltipStrings` → `getTooltip(ITooltipBuilder, …)`. `IIngredientRenderer#getTooltip(T, TooltipFlag)` is abstract and
  not deprecated. Both plugins end with 0 JEI `[removal]` warnings.
- **⚠️ JEI clickable areas are in screen coordinates.** Two upstream bugs: tank clickables returned GUI-relative rects
  (mouse actions on fluids never matched), and on `MultiModuleScreen`s `getGuiLeft()` returned the module-expanded
  `leftPos` while slots are drawn from `cornerX` (slot areas shifted by the side panel width). Key actions still worked
  — JEI only checks the area for mouse buttons. Mantle `MultiModuleScreen#getGuiLeft/getGuiTop` now return the main window
  corner.
- JEI recipe transfer is slot based (menu packets), so the transfer API only enters through slots.
- **Crafting Tweaks 21.10.1 + Balm 21.10.11:** no change needed. Its `pack.mcmeta` lacks `min_format`/`max_format`
  ("Couldn't load mod/craftingtweaks pack metadata", harmless).
- **JSON Things 0.16.0:** 4 breaks (`entityInside` in the flex liquid blocks, `appendHoverText(…, TooltipDisplay,
  Consumer)`). Test thingpack in `src/gametest/thingpacks`, synced into `run/gameTestServer/thingpacks` by
  `prepareGameTestThingpacks` (JSON Things only reads `<game dir>/thingpacks`). Upstream quirk fixed: `mob_effect_liquid`
  reads its level from `level`, with `burn_time` as the fallback for old thingpacks.

## Verification lessons

- **Review after every batch.** Independent reviews after each batch caught real regressions the battery did not: the
  smeltery alloy cache never invalidated by native fills, a stale duct mapping after an abort, a server crash when a
  smeltery shrank with its menu open, item loss/dupes in native side inventories, the `StackCopySlot` write-back, and the
  copy-ownership release that broke bound tools.
- **Safety-net gametests per block entity** (empty, filled, filled → empty) found the shipped empty-tank disconnect, the
  26 stale-client blocks and an upstream field that was written but never read (`insideCheck`).
- **Every hook removal needs a test that compares copies.** The copy-sharing regression compiled clean and only showed as
  "breaking a tool changes nothing" — test the copy, the original and the equipment snapshot.
- **Transactional semantics need red-first tests:** abort/nested abort/commit-once on every native handler, and the
  `slot_safety_*` gametests (8 of 9 red on the old code).
- **`runClientUiTest` now fails on any non-`ok` result** (the client always exits 0, so the task used to pass whatever the
  JSON said); verified red with the two JEI slot scenarios before their fix.
- The D8 reference run (1.21.8 tags in throwaway worktrees outside the workspace) with every PNG pair viewed found no
  regression; new scenarios were added for everything rewritten that no scenario showed (fluids in the world, casting
  cooling, AOE outline, carried-stack clicks, JEI clickables, JEI tooltips).
- uitest still needs an **unlocked screen** (`atio6axx.dll` at `glfwCreateWindow` while Windows is locked).
- `gradlew compileJava compileTestJava --rerun` reruns only `compileTestJava` — count warnings per task.

## Known issues (as of M5)

- **Stackable + damageable tools vs `ItemStack.validateStrict`** (from M4): still open, no code change; other
  `validateStrict` call sites not audited.
- Pre-existing, unchanged:
  - fluid buckets / copper cans render as a full fluid square (`MantleItemLayerModel.getMaskedQuadsForSprite` leaves the
    front/back quads unmasked, since 1.21.4);
  - the legacy `tconstruct:trim` modifier model is not re-registered (`PORT 1.21.4` breadcrumb in `ToolClientEvents`), and
    the generated `armor_trims` atlas still uses the pre-1.21.4 `trims/models/armor/*` paths (32 missing palette textures
    in the client log);
  - the book's structure smeltery tank still carries the legacy `{Amount, FluidName}` FluidStack NBT and fails to decode;
  - `MaterialBlockModel`'s item-side variant map is unbounded.
- Immersive Engineering stays excluded (1.21.1 only).
- 12 lustrous modifiers still need a mod providing `c:ores/<metal>` item tags.
- Log noise from third parties: Crafting Tweaks' `pack.mcmeta` without `min_format`/`max_format`; JSON Things parses every
  mod's `pack.mcmeta` with the things format (max 11) and logs kuma_api/balm/craftingtweaks/jei as "newer than 11", plus
  `File /things/.mcassetsroot does not exist`. The gametest server also logs 2 `Unprimed heightmap: OCEAN_FLOOR_WG` during
  worldgen tests.
- Tool data sharing is not covered for component patches taken without copying the stack (`getComponentsPatch`,
  `applyComponents`).
- `GreyToColorMapping` reproduces upstream's blue-channel overflow on purpose (parity decision above).
- `TabbedContainerMenu` decides the side inventory on both sides from the capability lookup; a mod whose client-side
  capability differs would desync the slot count (same as the legacy code).
- Not automated: shift/ctrl panel switching and shift → bucket units (real GLFW key state), the OS double-click
  detection, the gauge chat message/HUD tooltip and `/mantle tags_for held_fluid`.
